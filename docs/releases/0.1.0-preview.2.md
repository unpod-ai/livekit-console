# LiveKit Console v0.1.0-preview.2

This preview adds the first Agent Insights milestone for self-hosted LiveKit: optional post-session reports,
protected conversation viewing and SDK-reported turn timings. It is an early Phase 1 milestone, not full Cloud parity.

## Included

- Versioned, bounded report uploads authenticated with a separate service token.
- SQLite persistence correlated by room SID and job ID, including reports arriving before webhooks.
- Idempotent retries, conflict detection and configurable content retention (30 days by default).
- Administrator-only transcripts, tool/error/handoff markers, interruption flags, reported response/LLM/TTS timings
  and normalized JSON downloads.
- Python integration examples for `on_session_end` and compatible legacy worker shutdown callbacks.
- An implementation checklist and repeatable inbound-call acceptance procedure.

## Upgrade and enable

Back up the console database, then build from this tag using the existing Docker or Node.js deployment procedure.
Existing room/webhook history is retained; the report table is added automatically.

Collection stays disabled until a separate `AGENT_TELEMETRY_TOKEN` is configured on the console and agent.
Follow the [agent report setup guide](https://github.com/unpod-ai/livekit-console/blob/v0.1.0-preview.2/docs/agent-telemetry.md)
to integrate uploads and choose retention. Set `CONSOLE_URL` to an endpoint reachable from the worker; container
loopback refers to the container itself. Console login does not authorize private object storage.

## Limits

Only the documented Python SDK final-report format is supported. A real native `AgentSession` is required; other
agent pipelines need adapters. Reports contain sensitive conversation text and should be redacted at the source
as needed. Automatic PII redaction, live traces/logs, usage aggregation and synchronized recording playback remain
on the roadmap. Historical room webhooks cannot reconstruct past conversation reports.

## Validation

The regression suites cover report authentication, validation, correlation, duplicates/conflicts, retention, read
permissions and uploader transport/shutdown behavior. Browser checks cover disabled/empty/received/expired states,
escaped content, JSON download, viewer restrictions and horizontal overflow at a narrow viewport. Production builds
and tests run in CI. Repeat the acceptance procedure for your own provider, agent and storage setup.
