# LiveKit Console v0.1.0

One combined production release for the Cloud-parity implementation phases and final appearance controls. This console
administers one self-hosted LiveKit server; it does not provision LiveKit Cloud services.

- Rooms, sessions, participants, SIP calls/trunks/dispatch, ingress and egress with linked historical details.
- Authorized private recording playback through authenticated Range requests, synchronized session context and exports.
- Opt-in native agent reports, live transcripts/spans/logs, measured model usage/cost estimates and latency analytics.
- Connection/SIP diagnostics, collector health and durable agent/worker history across renames and restarts.
- Account roles with separate transcript, log and recording permissions; audit, retention, redaction, bounded exports,
  deletion controls, measured storage and in-console alerts.
- Restricted Docker host helper for allowlisted inventory, builds/logs, versioned write-only secrets and graceful
  deployment/drain/reconcile/rollback. Production targets may remain read-only; the console has no Docker socket.
- Dedicated browser test rooms with microphone/text/audio, repeatable scenarios and honest version/measurement coverage.
- Light, Dark and System appearance, persisted across navigation/reloads; System follows device changes.

## Upgrade

Take consistent backups of the application database and any old gateway control database before deployment. Existing
gateway installations migrate canonical accounts/default content grants/audit once into the application database,
preserving IDs/passwords and retained history. The project selector and project-scoped routes have been removed;
configure one server per console and use direct `/api/*`, `/webhook` and `/api/telemetry/*` endpoints. Keep the original
control snapshot for rollback. See the accounts/migration and Operations guides.

Configure the public `LIVEKIT_BROWSER_URL` when server-side APIs use loopback/private networking. Telemetry and
Docker management remain explicit opt-in integrations; the helper uses separate private config/token/state. Review
operator allowlists and retain read-only mode until a target is deliberately adopted.

## Evidence and boundaries

Validation includes 132 server tests, 72 Python tests, browser suites with 9 theme/administration and 7 deployment/RTC
checks, 34 isolated Docker checks and four live scenario responses across two runs. The release combines protected CI,
consistent migration/backups, isolated
real-Docker lifecycle checks and real provider-free LiveKit text scenarios. Final theme acceptance covers both palettes,
system updates, persistence, contrast and desktop/mobile layouts. Missing native metrics/provenance remain unknown;
browser results do not prove provider latency, billing or a served deployment version. Provider-backed tests can incur
provider usage; acceptance used a dedicated deterministic responder instead.

Managed inference/hosting/autoscaling, phone purchasing, telecom/Cloud billing and conditional OIDC are not included.
See the Cloud-parity checklist and deployment/telemetry/recording guides for configuration and limits.
