1. Agent Insights — first

  • Put a compact recording player above the workspace; hide an absent recording instead of rendering an empty panel.
  • Separate Transcript, Traces, Session logs and Metrics into URL-backed views.
  • Show conversation turns before SDK and collection metadata; avoid duplicate report/live transcripts.
  • Put job/report/collection identifiers and advanced information behind Details.
  • Open selected transcript items/spans in one details drawer; preserve recording seek and correlation links.
  • Use one clear no-telemetry state; retain distinct loading, error, disabled, partial and expired states.
  • Preserve live-only sessions and separate transcript, log and recording access grants.
  • Verify report switching, browser back/reload, exported data, drawer keyboard behavior and both themes/mobile.
  • Deploy and repeat checks on an existing populated session and an empty session.

2. Metrics and usage

  • Lead with measured latency summaries and charts, followed by stage breakdowns.
  • Use the shared time range by default; put exact timestamps and correlation inputs under Advanced filters.
  • Open contributing sessions/measurements in a drawer instead of an always-visible raw table.
  • Add session turn-latency/distribution charts and preserve turn-to-recording selection.
  • Separate token usage and speech usage; hide columns and tiles that do not apply to the measured stage.
  • Put coverage/methodology in contextual help; keep incomplete-data warnings visible and accurate.
  • Verify chart values, units, contributor selection and shareable URLs against retained measurements.

3. Agents and worker presentation

  • Default agent table: name, observed status, sessions, measured latency and last seen; load is optional.
  • Keep console/native IDs in row details, with copy controls; round percentages and duration values.
  • Collapse the empty Running now section and retain archived-agent/worker discovery.
  • Put useful overview summaries/charts before worker metadata.
  • Keep worker history, endpoints and identity links under Workers; remove deployment panels from agent screens.
  • Remove deployment panels from agent tabs; put alias management behind a deliberate action.
  • Verify renamed/archived agents, current workers and all related-session links.

4. Shared UI consistency

  • Replace repeated banners with concise status/help; preserve actionable warnings and errors.
  • Render only charts with relevant measurements; use one empty state when a quality source has no samples.
  • Standardize number, percent, time and latency formatting, table defaults and detail drawers.
  • Simplify narrow-screen headers and filters; verify settled layout after resize.
  • Verify keyboard focus, accessible control names, readable contrast and desktop/mobile in both themes.

5. Remaining workflows

  • Calls: readable overview and links first; provider IDs and SIP attributes in Details.
  • Egress: playback/session/status first; storage paths and request JSON behind Details.
  • Diagnostics: service/failure summaries first; exact source filters and snapshots under Advanced.
  • Testing: separate Test session, Scenarios and Results; reveal controls when relevant to connection state.
  • Operations/Settings: consistent grouping, concise collector health and clear actionable failures.
  • Keep repository traffic in Tools with its independent time range.
  • Repeat the live screen audit and record remaining limits before calling UI cleanup complete.

6. Visual polish — complete and deployed

Added from the fresh whole-console and control-pattern audits of 22 October 2026.

Implementation is complete and locally verified. Live acceptance is tracked separately below. Preserve the completed cleanup above.

Goal: a clear, elegant, visually engaging console, with calmer night colours and consistent patterns across all pages.

Implementation order: shared colours and controls, layout and typography, individual pages, then mobile and accessibility verification.

6.1 Colours and themes

  • Introduce charcoal backgrounds with subtly distinct card, field and overlay surfaces.
  • Replace repeated bright cyan panel headings and KPI values with neutral text; reserve softer teal for primary actions, selection and key measurements.
  • Reduce chart cyan/purple/orange saturation and use consistent semantic success, warning and error colours.
  • Verify text, control boundaries, focus and chart contrast in both themes; do not make supporting text harder to read.

6.2 Typography and spacing

  • Establish consistent page/section headings, readable labels, hints, table text and chart legends.
  • Standardise card padding, section spacing, table row heights and field alignment.
  • Reserve monospace for technical identifiers; keep names and descriptions readable.
  • Simplify summary units and precision, such as 3.97 s instead of 3971.95 ms; retain exact values in details.

6.3 Selects and dropdowns — priority defects

  • Unify select trigger surfaces, borders, chevrons, spacing, selected states and popup styling in both themes; remove the bright browser-blue mismatch where a custom desktop select is used.
  • Distinguish value selection from action menus; preserve accessible native mobile selection where appropriate.
  • Add searchable comboboxes for genuinely long agent/model lists; keep short lists simple.
  • Fix custom time-range keyboard focus: Enter/Space opening, Arrow Up/Down, Home/End, typeahead, selection, Escape dismissal and focus return.
  • Fix narrow-screen menu clipping and the hidden selected checkmark with viewport-aware positioning and collision handling.
  • Verify long labels, empty options, disabled options, scrolling and loading states without losing current values or URL filters.

6.4 Inputs and forms

  • Give text, number, date, select and textarea fields consistent surfaces, borders, padding and size variants.
  • Align labels, controls, hints and validation messages; retain explicit accessible labels.
  • Standardise hover, focus, disabled, loading and error states with visible restrained focus rings.
  • Group related settings into readable sections instead of many visually identical inputs.

6.5 Buttons, checkboxes and row actions

  • Define consistent compact/default/touch sizes and enlarge touch hit areas; remove uneven adjacent 26px/32px/44px controls.
  • Make primary, secondary and destructive actions clearly distinguishable without excessive bright fills.
  • Standardise checkbox/choice indicators, spacing, labels and checked/disabled/focus states.
  • Consolidate crowded row actions into accessible menus; preserve confirmations and permission boundaries.

6.6 Navigation, headers and tabs

  • Prioritise session, agent and call workflows; group deployments, diagnostics, testing and operations as secondary administrative tools.
  • Give titles and primary actions more room; make refresh/theme controls quieter and more compact.
  • Keep repository traffic's time range independent of project/session filters.
  • Distinguish top-level and nested investigation tabs with consistent selected/focus states; preserve working arrow-key navigation and deep links.

6.7 Tables and record details

  • Lead with readable names, context, status and duration; place UUIDs/provider identifiers in secondary text or details.
  • Improve wrapping, column widths and row density, particularly in worker/session lists and contributor drawers.
  • Preserve copy controls, native/source distinctions, cross-links and optional technical columns.

6.8 Charts and metrics

  • Reduce oversized sparse/single-bucket charts and explain measured sample counts without inventing trends.
  • Standardise units, decimal precision, legends, gridlines and interaction cues.
  • Highlight important measurements selectively; keep secondary series visually quieter.
  • Preserve missing-data gaps, source attribution, partial coverage and exact contributor selection.

6.9 Dialogs and drawers

  • Use compact dialogs for short creation forms rather than full-height mostly empty drawers.
  • Use wider drawers or stacked summaries for investigations; prevent repeated long names from squeezing essential data.
  • Keep readable context first and technical identifiers secondary; preserve keyboard focus, dismissal and state restoration.

6.10 Mobile layouts

  • Replace the permanent icon-only rail with a labelled navigation drawer suitable for small screens.
  • Compact stacked summary cards and place useful records earlier in the page.
  • Show essential record summaries before secondary columns instead of requiring repeated horizontal scrolling.
  • Verify popover positioning, touch targets, long labels, drawers and tabs at narrow and zoom-equivalent viewport widths.

6.11 Empty states and guidance

  • Use consistent empty states with one clear next action.
  • Hide unnecessary search/column tooling on truly empty lists while preserving active filters and recovery paths.
  • Make explanatory banners quieter; keep current failures, access denials and partial-data warnings prominent.

6.12 Page-specific refinement

  • Overview: prioritise current state and session activity; reduce competing shortcuts, bright counters and secondary breakdowns.
  • Agents/Insights: refine spacing, speaker/timestamp hierarchy, playback/job/export controls and nested navigation while retaining worker history.
  • Usage/Performance: compact filters, clarify summaries and sample counts, and reduce vertically stacked sparse charts.
  • Sessions/Calls/Egress: prioritise readable context, status, duration and playback over identifiers.
  • Telephony routing: simplify badge-heavy dispatch/trunk/number tables and repeated edit/delete actions.
  • Diagnostics: lead with service/call health and failure context; reduce repeated methodology while retaining coverage limits.
  • Operations/Settings: prioritise collector health; group retention, recording access, redaction and server/access configuration.
  • Testing: clarify start flow and run results; reveal comparison after meaningful selections.
  • Repo traffic: compact mobile cards and retention guidance while preserving its independent filter and history coverage.
  • Live rooms/Ingress/Tokens: provide clear next actions, consistent short-form patterns and useful field guidance.

  • Verify desktop/mobile, light/dark, keyboard, touch target sizes, reflow and accessible labels/selection states; record manual-device limits.
